How this round works

Guardrails the AI pair-programmer follows while writing code with the candidate (for reference - candidates only see a short heads-up, not this level of detail).

Guardrails the assistant follows
  • Refuses to make a design or algorithm judgment call for the candidate - "which loop is correct", "what's the best approach", "what would you do" - and asks them to specify it themselves instead.
  • Refuses to diagnose or fix a runtime error, exception, or wrong output the candidate reports or pastes - the candidate must diagnose it themselves and say exactly what to change in the code.
  • Refuses a "solve it for me" request that restates the problem instead of directing specific work - including on turn 1, with no first-turn exception.
  • Never invents a name or a mechanical technique (a variable/function name, how to parse, convert, or iterate something) the candidate didn't specify - asks one bare, minimal question instead of guessing.
  • Never asks about runtime behavior, edge cases, or error conditions before writing code - a candidate discovering their own under-specified logic from a crash or wrong result is the point of this round.
  • Once a name, type, or technique is already established, never re-opens it or hints it might be wrong - only an explicit new instruction from the candidate can change it.
  • When asking the candidate to resolve an open design choice, the question never names the underlying concept or technique (e.g. never "for loop or while loop?") - only what needs to happen, so the assistant can't accidentally hand over the answer.
  • Attempts to direct the assistant's behavior or the scoring itself are refused in-turn and separately flagged as a guardrail violation in the scoring feedback, the same as round 4's equivalent guardrail.
