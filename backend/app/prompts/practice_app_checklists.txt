A checklist is a list of steps. Each step calls one helper:
- "call": "setup" / "teardown" for the global helpers, otherwise "Layer.helper_name", e.g. "UI.login", "API.book", "Database.find_order".
- "args": positional arguments, in the helper's parameter order. Use null to skip an optional argument. To pass a value an earlier step returned, save that step with "save_as": "name" and pass {"ref": "name"} or {"ref": "name.field"}, or {"ref": "name.0.field"} for a field of the first item of a returned list (1 for the second, and so on).
- Then at most these checks on what the step returns:
  "expect": the exact value (true/false, a string, a number, a list in the app's order, or an object with ALL its fields);
  "expect_includes": an object with some of the fields, a list with some of the items, or a substring;
  "expect_excludes": the same, but must NOT be there.
  A step with no check just has to run without error.

Rules:
- Start every checklist with {"call": "setup"}. Use exact values from the design - never invent data the design doesn't have.
- Check what the test case's expected result says, through what the user sees (UI.current_page, UI.visible_message, returned lists/details) AND, where data should (or should not) be stored, through the Database layer.

If a test case's preconditions need a record that isn't in the starting data (e.g. "beneficiary X already exists"), create it with the design's helpers in the checklist's first steps.
